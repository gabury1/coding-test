## 배운 내용

### N-Queen 문제 해결 과정

#### 1. 첫 번째 시도: 2D 배열 + marking 함수
- 2D `metric` 배열로 공격 가능 여부 표시
- `marking(y, x, amount)` 함수로 8방향 마킹
- **문제점**: O(N) marking → 너무 느림 (TLE)

#### 2. 두 번째 시도: 1D 배열 최적화
- 4개 배열로 O(1) 체크: `rows`, `columns`, `cross_left`, `cross_right`
- 대각선 인덱싱:
  - `cross_left[y + x]` - ↙ 대각선
  - `cross_right[middle - y + x]` - ↘ 대각선 (middle = N-1)
- **여전히 문제**: check(), marking() 함수 호출 오버헤드 → TLE

#### 3. 최종 해결: 함수 인라인화
- check(), marking() 함수 제거 → dfs 안에 직접 작성
- 불필요한 파라미터 제거: `dfs(y, x, n)` → `dfs(y)`
- `middle = N-1` 전역화 → 매번 계산 X
- **결과**: 통과! ✅

### 핵심 교훈: Python 백트래킹 최적화

**Python에서 함수 호출은 매우 비싼 연산!**

백트래킹처럼 수십만~수백만 번 재귀가 도는 경우:
- 작은 헬퍼 함수(check, marking 등)를 만드는 대신
- 로직을 메인 재귀 함수 안에 **인라인**으로 넣어야 함
- 함수 호출 횟수를 최소화하는 게 가장 중요!

### 코드 비교

❌ **TLE 코드** (함수 호출 3번):
```python
for j in range(N):
    if check(y, j):        # 함수 호출 1
        marking(y, j, True)   # 함수 호출 2
        result += dfs(y+1, j, n-1)
        marking(y, j, False)  # 함수 호출 3
```

✅ **통과 코드** (함수 호출 1번):
```python
for x in range(N):
    if rows[y] or columns[x] or cross_left[y+x] or cross_right[middle-y+x]:
        continue
    rows[y] = columns[x] = cross_left[y+x] = cross_right[middle-y+x] = True
    result += dfs(y+1)  # 함수 호출 1번만
    rows[y] = columns[x] = cross_left[y+x] = cross_right[middle-y+x] = False
```

### N-Queen 핵심 아이디어

1. **행 단위 처리** - 각 행에 퀸이 정확히 1개 → 탐색 공간 대폭 감소
2. **1D 배열 체크** - rows, columns, diagonals 각각 1D 배열로 O(1) 체크
3. **대각선 인덱싱**:
   - ↙ 대각선: `y + x` 값이 동일
   - ↘ 대각선: `y - x` 값이 동일 → 음수 방지 위해 `y - x + (N-1)`

## 헷갈렸던 점

- 알고리즘은 맞는데 시간초과 나는 경우
- O(1) 체크가 O(N) 체크보다 항상 빠른 건 아님 (함수 호출 오버헤드가 더 클 수 있음)
- Python 최적화의 핵심은 **시간복잡도보다 함수 호출 횟수**
